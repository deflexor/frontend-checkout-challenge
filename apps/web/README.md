# Фронтенд (`@checkout/web`)

Магазин: каталог, корзина, оформление заказа и тестовая оплата. React 19 + TypeScript + Vite, без роутера и стор-библиотек: маршрутизация по `location.hash` (несколько экранов), состояние — React-контекст. Из зависимостей только `react`, `react-dom` и инструменты сборки.

## Запуск

```sh
npm ci                      # в корне репозитория
npm run dev                 # API на http://localhost:4000 (терминал 1)
npm run dev:web             # фронтенд на http://localhost:5173 (терминал 2)

npm run build:web           # сборка фронтенда в apps/web/dist
npm run preview:web         # локальный просмотр собранного
```

Адрес API задаётся переменной `VITE_API_BASE` (по умолчанию `http://localhost:4000`). CORS на API разрешает любой порт `localhost` — прокси не нужен.

## Устройство работы с API

Все запросы проходят один путь — компоненты не знают про `fetch`, статусы и конверты.

| Слой                  | Файл                                                               | Обязанность                                                                                                                                                                                                                                                                                          |
| --------------------- | ------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Транспорт             | `src/api/client.ts`                                                | Адрес API, токен и заголовки (включая `Idempotency-Key`), сериализация тела, `204` без тела, разбор конверта, сведение сетевых/HTTP-ошибок/ошибок разбора в один тип `ApiError` (код, сообщение, поля, requestId). 401 в любом запросе поднимает событие — приложение один раз перезапускает сессию. |
| Реестр запросов       | `src/api/endpoints.ts`                                             | Один объект: новый вызов API — строка с методом, адресом и типом ответа. Типы берутся из `packages/contracts`.                                                                                                                                                                                       |
| Опрос                 | `src/api/poll.ts`                                                  | Единый `pollUntil`: запрос → проверка → пауза, отмена через `AbortSignal`. Используется для оплаты и для заказа с незавершённой оплатой.                                                                                                                                                             |
| Загрузка и действия   | `src/lib/useApiData.ts`                                            | `useApiData` — данные/ошибка/загрузка с отменой и защитой от устаревшего ответа; `useAction` — мутация с блокировкой от двойного нажатия и той же `ApiError` на выходе.                                                                                                                              |
| Сессия и общие данные | `src/state/session.tsx`                                            | Восстановление токена, корзина, каталог, индексы `Map`, общий путь «изменил позицию → получил корзину заново».                                                                                                                                                                                       |
| Страницы              | `src/pages/*`                                                      | Только отображение и действия: получают готовые данные либо разобранную ошибку.                                                                                                                                                                                                                      |
| Общие правила         | `src/lib/format.ts`, `src/lib/validation.ts`, `src/lib/pending.ts` | Деньги и текст доставки; правила валидации и сборка тела запроса; черновики идемпотентности в `localStorage`.                                                                                                                                                                                        |

Ошибки обрабатываются один раз: `ApiError` уже содержит сообщение для показа и `fields` для привязки к полям формы (`body/customer/email` → поле `email`). Компоненты вызывают `ErrorBanner` или переносят сообщение под поле — повторного разбора транспорта нигде нет.

### Идемпотентность и восстановление

- Тело и ключ сохраняются в `localStorage` **до** запроса и удаляются после ответа. Потеря ответа или перезагрузка: приложение повторяет запрос с прежними телом и ключом и получает тот же заказ (200 вместо 201) — дубля нет.
- Сессия, корзина и текущий заказ восстанавливаются после перезагрузки: токен проверяется корзиной, невалидный заменяется новой сессией; незавершённая оплата подхватывается — `PAYMENT_IN_PROGRESS` заменяется поиском активной попытки у заказа, опрос продолжается.
- Опрос останавливается уходом со страницы (`AbortController` в cleanup), после терминального статуса и не даёт старому ответу перезаписать новый: каждый запуск `useApiData`/`watch` отменяет предыдущий.
- `CART_VERSION_CONFLICT` и `QUOTE_EXPIRED`: корзина перечитывается, расчёт пересоздаётся автоматически, введённые данные формы сохраняются (форма тоже живёт в `localStorage`), пользователь подтверждает заказ с новой суммой.

## Разбор обработки данных

Индекс позиций корзины в `src/state/session.tsx`:

```ts
const itemsByProduct = useMemo(
  () => new Map((cart?.items ?? []).map((item) => [item.productId, item])),
  [cart],
);
```

- **Частота вызова.** Строится только при смене объекта корзины: после мутации позиции, после `refreshCart` и при загрузке сессии. На рендеры по вводу текста в форме или по движению мыши не тратится — ссылка на `cart` не меняется.
- **Проходы.** Один проход `map` по `items` без промежуточных массивов: `new Map(iterable)` наполняется напрямую из итератора. `items` плотный массив объектов одной формы (V8 хранит как `PACKED_ELEMENTS`), дырок нет.
- **Память.** Одна `Map` на n позиций, живёт до следующей загрузки корзины. Взамен каталог и корзина делают `O(1)`-поиск количества и остатка на каждый рендер вместо линейного `find` по массиву на каждую карточку; аналогичный индекс `stockById` построен в корзине для остатков каталога.

Деньги нигде не пересчитываются на клиенте: подытог, доставка и итог всегда приходят из API (корзина, расчёт, заказ), `formatMoney` только приводит копейки к строке.

## Проверенные сценарии

Прогонялись в headless-браузере (Chromium, ширины 1280 и 390):

- каталог: недоступный товар без кнопки, добавление, счётчик в шапке;
- корзина: изменение количества, удаление, итог из API; пустая корзина не оформляется; удаление последней позиции показывает пустое состояние без ошибок;
- оформление: валидация полей, оба способа доставки с нужными полями, расчёт доставки и итог от сервера, пересчёт при смене доставки;
- карта: выбор тестовой карты по названию и маске, ожидание, успех, страница успеха с номером/составом/доставкой/суммой по данным сервера; отказ и отмена различимы, обе повторяемы на том же заказе;
- наличные: «Заказ оформлен, оплата при получении», без онлайн-оплаты;
- устойчивость: перезагрузка страницы после оплаты, перезагрузка во время обработки платежа, повтор заказа по ключу идемпотентности, форма не очищается при ошибке запроса;
- формы работают с клавиатуры, поля подписаны, ошибки связаны с полями через `aria-describedby`.
